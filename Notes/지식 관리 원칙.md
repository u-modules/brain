# 지식 관리 원칙

## 핵심 내용

폴더는 기록의 용도로 나누고, 분야는 태그로 분류합니다. 에이전트는 저장 요청을 받으면 기존 노트를 먼저 확인하고, 재사용할 수 있는 지식으로 정리합니다.

## 노트의 기본 형태

한 노트에는 다시 찾아볼 수 있는 한 가지 주제를 담습니다. 아래 항목 중 필요한 것만 사용합니다.

- **핵심 내용**: 무엇을 알아야 하는지 짧게 설명합니다.
- **설명·예시**: 이해에 필요한 근거와 사례를 담습니다.
- **내 생각·적용 방법**: 사용자가 직접 말한 생각과 적용 계획을 기록합니다. 에이전트의 제안은 따로 표시합니다.
- **출처**: 원문 링크나 제공받은 자료를 명시합니다.
- **관련 노트**: 실제로 존재하고 관련이 있는 노트를 연결합니다.

원문의 주장, 사용자의 생각, 에이전트의 추론을 구분합니다. 확인하지 않은 사실이나 개인 경험은 만들어 넣지 않습니다.

## 태그로 분야 구분하기

노트 맨 위의 `tags` 속성에 분야를 넣습니다. 옵시디언의 속성 편집기에서도 추가할 수 있으며, 속성 값에는 `#`을 붙이지 않습니다.

```yaml
---
tags:
  - 개발/프론트엔드
  - 개발/백엔드
---
```

한 노트에 여러 태그를 붙일 수 있습니다. `/`는 태그의 계층을 표현합니다. API 연동 노트처럼 양쪽에 해당하면 두 태그를 함께 사용합니다.

태그 예시: `개발/프론트엔드`, `개발/백엔드`, `개발/인프라`, `독서`, `생활`, `아이디어`, `지식관리/옵시디언`. 이 목록은 허용 목록이 아닙니다. 필요한 주제가 생기면 기존 표기를 확인한 뒤 추가합니다.

태그 뷰에서 태그를 선택하거나 검색창에 `tag:#개발/프론트엔드`를 입력하면 관련 노트를 찾을 수 있습니다. 태그 뷰가 보이지 않으면 설정 → 코어 플러그인 → 태그 뷰를 켭니다.

영어·한글 동의어를 따로 만들지 않고 기존 표기를 재사용합니다. 파일 경로나 코드에 등장했다는 이유만으로 태그를 붙이지 않습니다.

## 자격증 학습과 치트시트

자격증 시험 범위·학습 순서·오답의 이유는 Certifications/, 빠르게 찾아볼 명령·문법·비교표는 Cheatsheets/에 작성합니다. 시험과 무관하게 재사용할 원리는 Notes/에 정리하고 서로 연결합니다.

자격증 분야는 `자격증/자격증명` 태그를 함께 사용할 수 있습니다. 시험 일정·응시 자격·출제 기준은 최신 공식 자료와 확인 날짜를 남깁니다. 치트시트의 버전·환경·명령 검증 여부는 필요한 경우 명시합니다.

## 공개를 염두에 둔 작성

다른 독자가 이 대화를 몰라도 이해할 수 있도록 전제와 용어를 설명합니다. 출처와 직접 정리한 설명을 구분하고, 개인 식별 정보·회사 내부 정보·인증 정보는 공개 문서에 포함하지 않습니다.

개인 접수증·성적표·계정 정보가 담긴 스크린샷과 같은 첨부도 본문과 함께 공개 여부를 검토합니다. 공개용 노트에서 비공개 자료의 제목·경로·내용을 노출하는 링크를 만들지 않습니다.

공개하지 않을 자료는 `Private/` 아래에 저장합니다. 구체적인 저장 위치와 Git 제외의 한계는 [[공개와 비공개 관리]]를 따릅니다.

## 저장 흐름

1. 주제와 관련된 기존 노트를 검색하고 읽습니다.
2. 같은 주제면 기존 노트를 보완하고, 독립된 주제면 새 노트를 만듭니다.
3. 분류가 불확실한 내용은 Inbox에 둡니다.
4. 기존 설명과 충돌하는 내용은 조용히 덮어쓰지 않고 출처와 차이를 표시합니다.
5. 저장 후 다시 읽어 확인하고 변경한 문서와 내용을 알려줍니다.

대화 전문보다 배운 점, 결정 이유, 해결 방법을 남깁니다. 삭제·대규모 재분류·자동 커밋·푸시는 별도 요청이 있을 때 수행합니다.
