# Brain

개발 지식, 자격증 학습, 치트시트 등 다시 활용할 지식을 정리하는 옵시디언 보관함입니다. 공개 가능한 문서는 대화 맥락을 모르는 독자도 이해할 수 있도록 작성합니다.

지식 탐색은 [Home](Home.md), 작성 방식은 [지식 관리 원칙](Notes/지식%20관리%20원칙.md)에서 시작합니다.

## 공개와 비공개

일반 폴더는 공개 후보이며, 비공개 자료는 `/Private/` 아래에 둡니다. 이 폴더 전체는 Git에서 제외하지만, 같은 보관함의 MCP 접근이나 다른 동기화·웹 공개 도구까지 차단하는 설정은 아닙니다. 비공개 첨부도 반드시 Private/ 아래에 저장합니다.

[공개와 비공개 관리](공개와%20비공개%20관리.md)에서 저장 위치와 공개 전 확인 사항을 확인할 수 있습니다. GitHub 공개 저장소는 [u-modules/brain](https://github.com/u-modules/brain)이며, 웹사이트 배포는 구성하지 않았습니다.

## 구성

```text
현재 PC의 에이전트
  → MCP (인증된 로컬 HTTP)
  → Obsidian Local REST API with MCP
  → <저장소 루트>
```

Local REST API **5.5.2**의 내장 MCP 서버를 사용합니다. 별도 `mcp-obsidian` 서버는 설치하지 않습니다. 플러그인은 Obsidian 1.13.1 이상이 필요합니다.

이 보관함의 서버 주소는 `http://127.0.0.1:27123/mcp/`입니다. HTTP는 현재 PC의 루프백 주소에만 바인딩하고 Bearer 인증을 사용합니다. 외부 공개나 포트 포워딩을 하지 않습니다.

## 처음 열기

1. 옵시디언의 보관함 관리에서 **폴더를 보관함으로 열기**를 선택하고 이 저장소의 루트 폴더를 엽니다. 기존 보관함을 옮기거나 삭제하지 않습니다.
2. 이 보관함의 커뮤니티 플러그인을 허용하고 **Local REST API with MCP**가 켜져 있는지 확인합니다. 플러그인 코드는 이 PC에 설치되며 Git에는 포함되지 않습니다.
3. 플러그인 설정에서 HTTP 포트 `27123`, 바인딩 주소 `127.0.0.1`, HTTP 서버 활성화를 확인합니다. API 키는 복사해서 노트나 대화에 넣지 않습니다.
4. 현재 에이전트 클라이언트의 MCP 서버 목록을 새로고침하거나 클라이언트를 재시작합니다. 현재 실행 중인 대화에는 새 MCP 도구가 즉시 나타나지 않을 수 있습니다.
5. `obsidian-brain` 서버가 연결되면 아래 검증을 진행합니다.

옵시디언이 보관함을 닫거나 종료하면 연결할 수 없습니다. 다른 보관함에서도 같은 포트의 서버를 켜면 충돌하므로 보관함과 포트를 함께 확인합니다.

## 인증과 로컬 파일

- `.obsidian/plugins/obsidian-local-rest-api/data.json`: 플러그인 설정과 API 키. Git에서 제외합니다.
- 현재 계정의 `$CODEX_HOME/config.toml`: `obsidian-brain` MCP 연결과 인증 헤더. 이 저장소 밖에 보관합니다.
- `.obsidian/app.json`: 기본 수집함, 첨부 폴더, 링크 설정. Git으로 공유합니다.
- `.obsidian/community-plugins.json`: 사용하는 플러그인 목록. Git으로 공유합니다.

API 키를 재발급하면 클라이언트의 인증 헤더도 갱신해야 합니다. 플러그인의 설정 디렉터리 접근 허용은 끈 상태로 유지합니다. 전체 설정 파일이나 인증 헤더를 로그·노트·커밋에 붙이지 않습니다.

새 PC에서는 플러그인을 다시 설치하고 새 키로 연결합니다. 이 저장소를 복제하는 것만으로 인증까지 복제되지는 않습니다.

## 연결 검증

현재 보관함이 Brain인지 확인한 뒤 에이전트에게 요청합니다.

1. “옵시디언 MCP로 Home.md를 읽고 보관함이 Brain인지 확인해줘.”
2. “MCP로 지식 관리 원칙을 검색하고 태그 목록을 확인해줘.”
3. “현재 열린 노트의 경로를 MCP로 알려줘.”
4. “Inbox/MCP 연결 확인.md에 `한글 저장 확인`을 저장하고, 다시 읽어 확인해줘.”
5. “방금 노트에 한 줄을 추가하고 기존 내용이 유지됐는지 확인해줘.”

4~5번은 사용자가 검증을 요청했을 때 수행하며, 완료 후 확인용 노트를 제거합니다. 열린 노트가 없으면 열려 있지 않다고 알려야 합니다. 검색 결과가 비어 있어도 읽기·쓰기 성공으로 간주하지 않습니다.

앱을 종료한 상태의 연결 실패는 정상적인 제약입니다. 연결 실패 시 저장 완료로 보고하지 않고 내용을 대화에 남깁니다.

## Git과 복구

노트는 Markdown으로 저장합니다. 자동 커밋·푸시는 설정하지 않습니다. 비공개 지식은 저장소 공개 범위를 확인한 후 올립니다. Git에 커밋하지 않은 내용은 Git으로 복구할 수 없으며, Git 자체가 별도 백업을 대신하지는 않습니다.
